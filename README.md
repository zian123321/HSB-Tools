# 检测拦截差异监控机器人

常驻轮询内部检测系统的「已拦截」记录，按同一设备（IMEI）回溯历史检测单做对照，自动比对两份报告的现场检测项差异，发现真差异时通过钉钉机器人推送告警，并按条码段规则署名对应负责人。

> 本仓库为脱敏后的通用版本：不含任何账号、密码、接口域名、机器人凭证和真实人员信息，相关内容全部外置到本地配置。

## 功能特性

- **轮询拦截记录**：在可配置时间窗内拉取「已拦截」记录，只要条码 + IMEI 非空即纳入处理，不限制条码格式。
- **历史对照单匹配**：同一 IMEI 下回溯历史检测单，优先选取同前缀（前 3 位）的最新单；无同前缀候选时再跨段取最新兜底。支持 IMEI / IMEI2 / SN 兜底匹配。
- **前端口径比对**：仅比对前端实际展示的现场检测项；只把「双边都有有效值且结果不同」判定为真差异；单边缺失、空值、未检测、无法质检等情况单列参考，不计为异常；前端隐藏属性项走黑名单过滤。
- **跨模板提示**：新旧条码首字符一个数字开头、一个字母开头时，判定采集模板不同、检测项口径不可比，不自动逐项下结论，仅提示人工核实。
- **钉钉告警与署名**：差异 / 失败 / 跨模板提示按需推送到钉钉群；按条码段规则映射负责人标识并真 @（需本人在群内且绑定对应手机号）。
- **稳定性保障**：单条记录异常隔离不影响整体；登录态失效自动重登；连续 N 轮接口硬失败才告警一次，避免抖动刷屏；同一设备告警带冷却期；非播报时段静默等待。

## 工作流程

```
登录鉴权 → 拉取时间窗内已拦截记录 → 过滤有条码+IMEI 的目标记录
   → 按 IMEI 找历史对照单 → 分别拉取两份报告详情 → 解析检测项字典
   → 真差异 / 单边缺少 / 跨模板判断 → 生成消息 → 钉钉推送（或控制台预览）
```

## 快速开始

### 1. 环境要求

- Python 3.8+
- 依赖：`requests`

### 2. 安装依赖

```bash
pip install -r requirements.txt
```

### 3. 填写本地配置

```bash
cp config.example.py config.py
```

编辑 `config.py`，填入登录账号、接口地址、钉钉机器人 webhook、负责人手机号等。`config.py` 已在 `.gitignore` 中，不会提交到仓库。

> 也可以不使用 `config.py`，改为设置同名环境变量；脚本读取顺序为：本地 `config.py` → 环境变量 → 脚本内默认占位值。

### 4. 运行

```bash
python imei_monitor.py
```

看到 `[OK] 登录成功，获取token` 与 `[INFO] 监控启动，开始轮询拦截记录...` 即启动成功，进程常驻，默认每 60 秒一轮。

停止：在控制台按 `Ctrl + C` 或关闭窗口。

## 配置项说明

| 配置项 | 作用 | 默认值 |
| --- | --- | --- |
| `USERNAME` / `PASSWORD` | 登录系统的账号密码 | 空（占位） |
| `LOGIN_URL` | 登录接口地址 | 占位域名 |
| `IMEI_LOCK_URL` | 拦截记录列表接口 | 占位域名 |
| `DEVICE_RECORDS_URL` | 历史检测记录接口 | 占位域名 |
| `DETECT_DETAIL_URL` | 报告详情接口 | 占位域名 |
| `IMEI_LOCK_UPDATE_URL` | 自动通过接口（待接入） | 占位域名 |
| `DINGTALK_WEBHOOK` | 钉钉机器人 webhook | 空（占位） |
| `DINGTALK_KEYWORD` | 机器人安全设置的自定义关键词，需与钉钉后台一致 | `【检测监控】` |
| `DINGTALK_ENABLED` | 是否真实推送钉钉；`False` 时仅控制台预览 | `False` |
| `SEND_STATUS_NOTIFY` | 错误 / 连续失败告警是否推送 | `True` |
| `SEND_STARTUP_NOTIFY` | 是否推送服务启动成功通知 | `False` |
| `OWNER_MOBILES` | 负责人标识 → 钉钉绑定手机号映射 | 空字典 |
| `BROADCAST_START_HOUR` / `BROADCAST_END_HOUR` | 每日播报时段（左闭右开） | `10` / `20` |
| `POLL_INTERVAL` | 轮询间隔（秒） | `60` |
| `ALERT_COOLDOWN` | 同一设备重复告警冷却（秒） | `3600` |
| `RECORD_LOOKBACK_DAYS` | 历史检测单回溯天数 | `30` |
| `MAX_HISTORY_PAGES` | 历史记录翻页硬上限 | `20` |
| `FAIL_ALERT_THRESHOLD` | 连续 N 轮接口硬失败才告警一次 | `3` |

## 署名规则

条码段与负责人标识的映射在 `get_owner()` 中维护，具体姓名 / 手机号在 `config.py` 的 `OWNER_MOBILES` 中配置：

| 条码特征 | 负责人标识 |
| --- | --- |
| `020` 开头，或字母 + `011` 开头 | `OWNER_A` |
| 纯数字 `010` 开头，或字母 + `010` 开头 | `OWNER_B` |
| 其余段 | 不署名 |

## 推送消息类型

- **差异预警**：双边有效结果不一致，列出差异项与新旧取值。
- **未识别出异常项目**：无真差异，但存在单边缺少项（检测范围不一致，仅供参考，不计异常）。
- **报告获取失败**：任一报告详情拉取失败，跳过本次比对并通知。
- **模板不同提示**：新旧条码分属数字 / 字母两类开头，提示人工核实差异。
- **运行异常告警**：连续多轮接口失败或全局异常时通知。

## 脱敏与安全声明

- 仓库内**不包含**任何真实账号、密码、内部域名、钉钉 access_token、人员姓名与手机号；上述均为占位示例。
- 本地真实配置写在 `config.py`，已被 `.gitignore` 忽略，提交前请再次确认未把 `config.py`、`.env`、日志文件加入版本库。
- 钉钉真 @ 要求：被 @ 人在群内，且配置的手机号是其钉钉账号本人绑定号；否则消息里的号码会被脱敏展示，不触发提醒。

## 已知限制 / 待办

- **自动通过**：命中特定轻微差异时自动放行的接口（`imeiLockUpdate`）Payload 尚未接入，`auto_pass_record` 目前为占位逻辑。
- **冷却为内存态**：重复告警冷却记录保存在进程内存中，进程重启后清空；如需跨重启去重，可将已告警记录落盘持久化。
- **接口字段适配**：不同系统模板的检测项字段名可能不同，黑名单与字段映射需按实际报告结构调整。
