# 部署与换证说明

## 一句话原理

把整个看板文件夹拷到一台常开机的内网电脑，运行常驻服务后，它按固定间隔自动拉取数据、生成最新看板，并在局域网开一个网页地址给同事看。查看者无需安装任何软件，打开网址即是最新数据。

## 一、文件清单（首次部署先认一遍）

| 文件 | 作用 |
| --- | --- |
| `拉数脚本.py` | 主程序：拉三个数据源 + 合并去重 + 生成看板 |
| `常驻看板服务.py` | 调度 + 局域网网页服务（日常就跑这一个） |
| `更新凭证.py` | 凭证过期时一键换证工具 |
| `自动登录.py` | 可选：浏览器自动化自动登录刷新凭证 |
| `诊断.py` | 只读探针，逐源分类报错并写 `诊断结果.txt` |
| `模板.html` | 看板页面模板（含状态条） |
| `config.json` | 可调参数（间隔、端口、每页条数、UA、自动登录账号），由 `config.example.json` 复制而来 |
| `凭证.json` | 登录凭证（唯一存放处，严禁外发） |
| `数据缓存.json` / `验货缓存.json` / `拍照缓存.json` | 三源历史数据，增量合并、自动去重；拉取失败时兜底，页面不空白 |
| `backups/` | 缓存自动备份（原子写入前备份旧文件，保留最近 3 天） |
| `state.json` | 运行状态记录（最近成功时间、凭证状态，排障用） |
| `服务日志-YYYYMMDD.txt` | 按天切割的运行日志，自动保留 14 天 |
| `产出看板.html` | 最终看板页面（网页服务直接返回它） |

## 二、准备电脑（只需一次）

1. 装有 Python 3（安装时勾选 *Add Python to PATH*；命令行 `python --version` 能出版本号即可）。
2. 把整个看板文件夹原样拷到本机任意目录，例如 `D:\tools\dashboard\`。
   - 所有脚本、模板、缓存必须**平铺在同一个文件夹**里，不要多套一层子文件夹；
   - 缺少 `拉数脚本.py` / `模板.html` 会直接报"找不到文件"。

## 三、试运行（窗口模式，先确认能跑通）

1. 在文件夹地址栏输入 `cmd` 回车，打开命令行。
2. 执行：`python 常驻看板服务.py`
   - 不要直接双击文件名（可能被关联到编辑器）；必须用 `python` 开头调用。
3. 首次运行若弹 Windows 防火墙窗口 → 点「允许访问」。
4. 看到下面输出即成功（IP 以本机实际为准）：
   ```
   局域网看板地址：http://<本机IP>:8899/
   本机打开：http://127.0.0.1:8899/
   下一轮拉数时间：xx:xx:xx（对齐到 :00 / :30）
   ```
5. 浏览器先开 `http://127.0.0.1:8899/` 自检；再用手机连同一内网打开局域网地址，确认同事视角。

## 四、设置开机自启（之后无人值守）

- 注册自启：`python 常驻看板服务.py --install`（Windows 计划任务，登录后自动后台运行）
- 取消自启：`python 常驻看板服务.py --uninstall`
- 手动看日志 / 重启：先关掉后台进程，再用第三步窗口模式运行。

## 五、日常维护

- **调度**：默认 30 分钟一轮，对齐 `:00/:30`；电脑休眠唤醒后自动补拉一轮，不追跑堆积任务。改频率 / 端口：编辑 `config.json` 的 `interval_seconds`（秒，3600=1 小时）、`port`，重启服务生效。
- **容错**：单个数据源网络抖动自动退避重试 3 次；某一源失败不影响另外两源，页面用旧缓存兜底继续展示。
- **数据安全**：缓存先写 `.tmp` 再原子替换，写入前自动备份到 `backups/`（留 3 天），中途断电也不会把缓存写坏。
- **状态条**：看板顶部显示绿 / 红 / 黄状态点、更新时间、三源各自条数。红点 = 凭证待换证；黄点 = 某源异常但旧数据兜底；绿点 = 全部正常。
- **日志**：`服务日志-日期.txt` 按天生成，自动清理 14 天前旧日志。
- **失败降噪**：连续取不到新数据时，服务自动把探活间隔拉长（30→60→120 分钟封顶）；成功一次立即回到正常间隔。
- **排障留痕**：每轮完整 stdout/stderr 覆盖写入 `最近拉数输出.txt`；窗口看不全时打开它即可定位真实报错。

## 六、凭证换证（唯一通常需要人工的环节）

凭证由服务器签发，工具无法让它永不过期。

**现象**：状态条红点"凭证待更新"，日志出现 `3001 登陆超时` / 请重新登录 / 401 / 403。

**步骤**：

1. 浏览器正常登录业务系统，随便打开一个列表页；
2. `F12` → Network（网络）→ 找到接口请求 → 右键 *Copy* → *Copy as cURL*；
3. 推荐方式（Windows 避免长引号报错）：把整条 cURL 粘贴存为同目录 `curl.txt`，再执行：
   ```cmd
   python 更新凭证.py curl.txt
   ```
   也支持：`python 更新凭证.py "粘贴整条cURL"`，或不带参数运行后粘贴、`Ctrl+Z` 回车结束；
4. 工具会先调登录信息接口校验，通过才写入 `凭证.json`；下一轮自动生效，无需重启服务；
5. 多个系统共用同一凭证，换证一次全覆盖。

**长期免换证方向**（需要管理员配合，另行评估）：

- A. 申请长效 API 凭证（最推荐、最合规）；
- B. 抓包确认是否存在 refreshToken 刷新接口；
- C. 无人值守自动登录（受验证码 / 风控限制，且有合规风险，最后考虑）。

## 七、常见故障排查

| 现象 | 处理 |
| --- | --- |
| 网页打不开 | 确认服务窗口还在运行；确认同一内网；换端口改 `config.json` 后重启 |
| 页面一直是旧数据 | 看状态条是否红点；按第六步换证；看 `state.json` 的 `last_success` |
| 日志反复"未取到新数据 / 退出码 1" | 打开 `最近拉数输出.txt` 看真实原因；或跑 `python 诊断.py` 生成 `诊断结果.txt`：3001=凭证失效换证；连不上=查内网 / 防火墙；证书错误=检查本机根证书 |
| 想查历史缓存 | 直接打开三个缓存.json（UTF-8）；`backups/` 里有每日备份 |
| 换电脑 / 换目录 | 重新走第二、三、四步；`凭证.json` 可随文件夹拷贝 |

## 安全须知

- 网址只在内网访问；不要在路由器 / 防火墙做公网映射，不暴露到互联网。
- 网页只开放看板页面；脚本、`凭证.json`、缓存、`config.json` 一律返回 404，勿改动该拦截逻辑。
- `凭证.json` 含登录身份，严禁外发、严禁上传到公开网盘或公开链接。
- 数据仅限获得授权的工作场景使用。
